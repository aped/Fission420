# ADR 0015: Edge and vertex identity, more referenceable faces, piece seeds

Status: proposed (2026-10-14)

## Context

ADR 0003 made face references semantic: `FaceRef { feature, role }` names a face by the feature
that generates it and the role the face plays (extrusion caps, the side of sketch line `e`, an
imported face, a pattern occurrence's face, a chamfer face). The frame comes from the feature
definition; the B-rep only validates it; an ambiguous or missing match is a `BrokenReference`,
never a guess. That rule has held up, but the vocabulary is too small for Fusion-style modelling:

* Edges and vertices have no identity at all. `Fillet { a, b }` and `Chamfer { a, b }` name an
  edge as the intersection of two planar faces, which works for one straight edge of a prism and
  for nothing else (a curved edge, two edges between the same two faces, an edge picked in the
  viewport).
* Faces of revolve, loft, sweep, hole, fillet and curved extrusion walls (sides of arcs,
  ellipses, splines) cannot be referenced, so a sketch, a joint or a measurement cannot attach to
  them.
* Split pieces are identified by position (ADR 0003, "Cuts that split a body": bounding-box
  order). An upstream edit that reorders pieces silently moves a downstream feature to another
  piece. That is the one silent retarget left in the reference model.
* The viewport picks faces only, by a brute-force ray test over every triangle
  (`rcad-viewport/src/mesh.rs`). Group ids are face indices in the tessellation, which follow the
  B-rep face order of one evaluation; they are display handles, not identities.

Topological naming in commercial modellers is known to be the hard part of history-based
modelling; there is no general solution. This ADR keeps ADR 0003's position (definition first,
the B-rep validates, ambiguity is an error) and extends it in stages that each ship on their own.

## Decision

### Vocabulary

```text
FaceRef  { feature, role: FaceRole }                         (unchanged)
FaceRole += ExtrudeSide{entity}       now also for arcs, ellipses, splines (curved walls)
          | RevolveSide{entity} | RevolveCap{Start|End}
          | LoftSide{section_a_entity, section_b_entity} | LoftCap{A|B}
          | SweepSide{entity} | SweepCap{Start|End}
          | HoleWall | HoleFloor | CboreWall | CboreFloor | CskCone
          | FilletFace{edge: EdgeRef} | LoopFilletFace{segment: entity}
          | Piece{piece: PieceKey, of: Box<FaceRole>}       faces of a split piece
EdgeRef   { a: FaceRef, b: FaceRef, nth: Option<EdgeKey> }
EdgeKey   { generator: Option<entity>, fingerprint: Fingerprint }
VertexRef = Corner{edges: [EdgeRef; 2]} | EdgeEnd{edge: EdgeRef, end: Start|End}
Fingerprint { kind: Plane|Cylinder|Cone|Sphere|Torus|Line|Circle|Other,
              params (normal / axis / radius), centroid, area or length, bounds }
PieceKey  { seed: [f64; 3] in the owning feature's definition frame, volume, bounds }
```

An edge is a connected component of the shared boundary of its two faces. Its provenance is
therefore the pair of face roles, for example "side face of line e3 of Extrude1 ∩ end cap of
Extrude1" is the top edge generated by e3. `nth` is only needed when the two faces share several
components (a slot cut through a wall meets the wall's cap in two edges); it is disambiguated by
the generating sketch entity where one exists, else by fingerprint.

### Resolution rules

1. **Definition first** (as ADR 0003). The expected surface or curve comes from the generating
   feature (profile entity x operation), placed through later moves and patterns.
2. **Validate against the B-rep.** Exactly one face (edge component) must match by surface
   (curve) identity: planes by plane and outward normal, cylinders, cones, spheres and tori by
   their analytic parameters, edges as boundary components of two resolved faces.
3. **Fingerprint gate.** A match whose fingerprint moved by more than the upstream edit explains
   (a parameter-driven change is fine, a jump to another region is not) is reported: `Warning`
   (resolved, changed, with the reason) or `Error` (ambiguous). The fingerprint never selects
   among candidates by nearness; it only confirms or rejects the unique definition match.
4. **Edges.** One component: bind. Several: `nth` by generator entity, else by unique fingerprint
   overlap (curve distance within the edit-explained displacement), else `BrokenReference` listing
   the candidates for a repair UI.
5. **Pieces.** When a cut or split first produces a piece, the feature stores a seed point
   strictly inside it (in the owner's definition frame, so it moves with the definition). On every
   regeneration each stored id goes to the unique new piece containing its seed (exact
   point-in-solid where available; winding number with a margin otherwise, refusing when the
   seed is within the margin of a boundary). No piece, or several, is a `BrokenReference` on the
   dependents, never a positional fallback. Bounding-box order stays only for naming new pieces.
6. **Imported faces.** `Imported { face }` gains the face's fingerprint recorded at import;
   resolution checks it, so a changed source file cannot silently move a reference.

### Picking (display side)

* The tessellation emits, next to the triangle-to-face table, an edge-polyline table and a vertex
  table keyed by *provisional* refs: the face indices of the current evaluation for faces, the
  pair of adjacent face indices plus a component number for edges, edge ends for vertices. The
  document maps provisional refs to `FaceRef`/`EdgeRef`/`VertexRef` (the resolution above run
  backwards); a provisional ref is never stored in a feature.
* Picking runs on a bounding-volume hierarchy over triangles, edge segments and vertices, in
  `rcad-viewport`, with a pixel tolerance (screen-space distance for edges and vertices) that is
  independent of the model tolerances in `rcad-kernel` (`docs/TOLERANCES.md`). Priority on a
  tie: vertex, then edge, then face, as in Fusion.
* Budget: a pick over a million triangles in under 2 ms on the reference desktop (release
  build), so hover highlighting stays interactive.

### Format

* New fields are `serde(default)` and written only when present, gated by the document version
  in the same way as earlier additions; files that use none of them keep loading in older builds.
* The new structs reject unknown keys (`deny_unknown_fields` or an explicit refusal), so a newer
  document is never half-read by an older build that would ignore the new keys.
* Migration: `Fillet { a, b }` and `Chamfer { a, b }` load as an edge set
  `[EdgeRef { a, b, nth: None }]`; `pieces: Vec<BodyId>` loads as `Vec<PieceSlot { body, seed }>`
  with seeds computed on first load from the current evaluation (the document is marked changed
  and the load report says so). Imported faces get their fingerprints the same way.

## Staged plan

| Stage | Content | Format |
|---|---|---|
| 1 | Piece seeds and imported-face fingerprints; commands that carry a face pick check the document revision it was made on. Display side: edge-polyline and vertex tables keyed by provisional refs, BVH picking of faces, edges and vertices with a pixel tolerance. No new stored vocabulary. | piece seeds and fingerprints |
| 2 | Per-feature health (healthy / warning / error / suppressed / rolled back) so later stages can break a reference without blocking edits. | health is computed, not stored |
| 3 | New face roles for revolve, loft, sweep, hole, fillet faces and curved extrusion walls; face candidates for them; picking maps display faces to them. | new roles behind the version gate |
| 4 | `EdgeRef` and `VertexRef`, edge and vertex picking bound to them, fillet and chamfer on edge sets, joint origins on vertices and edges. `Fillet { a, b }` migrates to an edge set. | edge sets |
| 5 | Repair UI: re-select in Edit Feature, a lost-references dialog (re-link, unlink, delete keeping dependents), ghost display of the lost entity. | none |

Each stage ends with tests that edit an upstream parameter and check that every reference either
follows the same physical entity (checked by an independent oracle such as a centroid or a seed
point) or reports `BrokenReference`; a positional retarget counts as a failure.

## Consequences

* References stay deterministic functions of the definition and the B-rep; the B-rep face order
  (which varied between processes before the boolean's topology walks were made order-stable)
  never decides an identity.
* Some edits that "worked" by positional luck now stop with a `BrokenReference` and a repair
  prompt. That is the intended trade: a visible error instead of a silently different part.
* Edge identity depends on face identity, so faces without a role (fillet faces before stage 3,
  imported faces without fingerprints) cannot anchor an edge until their stage lands.
* Not solved: references into geometry whose topology changes class under an edit (a face that
  vanishes because an offset exceeds a concave radius, an edge that splits into two). Those are
  reported as broken, not remapped.
