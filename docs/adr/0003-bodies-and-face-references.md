# ADR 0003 — Multi-body documents, explicit operation targets, planar face references

Status: accepted (run 3, 2026-10-10)

## Context
Runs 1–2 had one implicit base body: the first Extrude/Revolve created it and every Cut/Pocket
cut "the" body. Face references were limited to extrusion caps. Session 3 needs several named
bodies, Join/Cut with explicit targets, imported B-rep and mesh bodies, sketches on side faces,
cut floors and imported planar faces, and honest broken/ambiguous-reference diagnostics.

## Decision

### Body identity
* `BodyId(u32)` is allocated from `Document::next_body_id`, monotonic, never reused. It is
  stored in the feature that creates the body (`Operation::NewBody { body }`, import features
  list the ids of every body they create). Vector positions and the current selection never
  resolve anything during regeneration.
* `Document::bodies: Vec<BodyInfo { id, name, visible }>` holds user-facing metadata. Every
  `BodyInfo` must be created by exactly one feature and vice versa (validated on load and
  after every transaction). Rename / show / hide are ordinary undoable transactions.
* Body-consuming features name their target explicitly: `Operation::Join { target }`,
  `Operation::Cut { target }`; legacy `Cut`/`Pocket` features get a `target` field.
* Geometry kinds: `Brep` (exact Truck solid) and `Mesh` (triangle mesh, STL import). Exact
  operations on a mesh body are refused with an explanation.
* Imported bodies are *base features*: `ImportStep` / `ImportMesh` features embed the source
  bytes in the document's blob table (`Document::blobs`, content-hashed) plus the import options
  (unit scale). Regeneration re-imports from the embedded bytes, so a native file never needs
  the original path. No source feature history is recovered or implied.

### Migration
Native format v3. v1/v2 files load through a migration: the first Extrude/Revolve gets
`BodyId(1)` (named after the feature, visible), later Cut/Pocket features get `target = 1`.
Feature ids and geometry are unchanged. Saves write v3; older binaries refuse v3 (version check).

### Planar face references
`FaceRef { feature, role }`, roles:
* `ExtrudeEndCap` / `ExtrudeStartCap` (run 2): caps of an extrusion. For a Cut extrusion
  the end cap is the floor of a blind cut, outward normal pointing back toward the opening.
* `ExtrudeSide { entity }`: the planar side face generated by sketch line `entity` of the
  extruded profile (entity ids are stable sketch ids). Arc entities generate curved faces and
  are refused.
* `Imported { face }`: planar face with stable import index `face` of an imported solid; the
  plane (and its frame) are recorded at import time and persisted with the feature result
  being recomputed from the embedded bytes.

Resolution: the frame is derived from the generating feature's *definition* (never from the
B-rep), then validated against the current B-rep of the body that owns the face: exactly one
planar face of that body must lie in the plane with the same outward normal. Zero faces →
`BrokenReference` ("face no longer exists"); more than one → `BrokenReference` ("ambiguous:
split into N faces"). No nearest-centroid or index guess is ever used. Repair is explicit: the
`SetSketchPlane` command re-attaches a sketch to another plane/face (one undo step; the
sketch's local coordinates are kept, and the UI previews the new frame first).

Frames are right-handed and depend only on definition data:
* side face of line a→b (in the profile's CCW order about the sketch normal n): origin = a
  on the sketch plane, x = (b − a)/|b − a|, z = outward normal x × n (negated for a Cut: the
  wall of the removed region faces into the cavity), y = z × x (along n for New/Join);
* extrusion caps: origin = sketch origin offset along the extrusion direction, x = sketch x,
  z = outward normal (cut floor: pointing back toward the opening);
* imported planar face: origin = face area centroid at import, z = outward normal,
  x = the world axis least aligned with z projected into the plane, y = z × x.
Edge ordering therefore never flips axes.

### Extrude operations
`FeatureKind::Extrude { sketch, distance, operation, extent, reverse }`:
* `extent`: `Distance` (uses `distance`) or `ThroughAll` (Cut only; both sides of the sketch
  plane along its normal, cutter length = target extent along the normal + margin
  `max(1 mm, 5 % of the target bbox diagonal)` on each side, so caps are never coplanar).
* Direction: along the sketch normal, except when the sketch plane holds a face of the target
  (whatever plane the sketch was made on): a Cut then goes into the material and a Join away
  from it (along the face's outward normal) by default. `reverse` flips the default; a
  reversed blind Cut or Join from a face (pointing into air / into the material) is refused,
  so in that case Reverse has no valid use and the UI disables it.
* Join from a face sketch: Truck 0.6 booleans return nothing for coplanar contact (measured,
  spike 2026-10-10), so the tool is extended `δ = min(0.5 mm, distance/2)` *into* the support
  side. This is only correct when the profile lies inside the support face; the regenerator
  checks the profile against the face region and refuses otherwise (product limit, explicit).
* Blind cut from a face sketch starts a margin outside the face (run-2 rule) and ends exactly at
  depth, except when the floor lands exactly on a face whose material lies on the tool's side
  (a cut through the full thickness): the floor then moves a margin past it, which removes
  exactly the same material and avoids a coplanar boolean.
* A Join that does not touch the target is reported as such before the face-containment rule.
* A Join/Cut tool whose bounds do not overlap the target is refused ("does not intersect").
  Results must be one closed shell; a multi-shell result is refused (no silent split bodies).
  On failure the document keeps the last valid model.

## Consequences
* A coplanar Join flush with a face edge, or a cut that splits a referenced face, produces an
  explicit reference error; the user re-attaches.
* Measurements become per body.

### Sketch entity ids are persistent names
Side-face references name sketch entities by id. Removing an entity retires its id
(`Sketch::retired_entity_ids`, only serialized when non-zero); new entities never reuse a
retired id, and `EditSketch` refuses a sketch that gives an existing or retired id to an entity
of a different kind. An edited line keeps its identity when its endpoints change.
